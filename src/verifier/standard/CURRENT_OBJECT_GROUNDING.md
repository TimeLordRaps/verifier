# Versioned current-object grounding: simulation independence objective

Verifier Standard (VSTD) uses simulation (SIM) as an admitted object kind. This candidate registers exactly one objective in semantic namespace `verifier-current-object-obligations-1`: `SIM-5.1`. The coordinate is an objective index within the current tier 5, independence. It is not the legacy `SIM-5.1` mainstay-binding obligation under `verifier-domain-obligations-1`; no legacy result transfers.

## Exact proposition

Within the externally selected finite SIM model, every reachable state has at least one retained outcome for every declared action, and every such outcome remains inside the declared simulation partition, acquires no capability, and has no outside write, external actuation, or external export effect.

This is **finite declared capability/effect confinement** only. The state/action alphabet, partition and capability inventory are retained declarations. A passing check cannot establish physical host isolation, an exhaustive real-world action alphabet, external-resource authority, ownership, privacy, consent, governance, full SIM tier 5, or object-profile conformance. `object_profile_conformance` and `sim_tier_5_conformance` remain `NOT_ESTABLISHED` for all outcomes. An objective PASS is not a tier PASS.

The proposition registration binds the semantic namespace, coordinate, exact proposition text, model-relative scope, prerequisites and exclusions to a canonical digest. The request externally selects that registration, the complete collection commitment, exact SIM object digest, SIM identifier, finite-model evidence digest, checking limits and policy digest. Collection evidence and isolation evidence are retained as bounded canonical JavaScript Object Notation (JSON) bytes in a content-addressed store. The certificate stores these bytes, evaluated result and its canonical digest; it carries no executable code or admission authority. Offline recheck requires an independently supplied expected request and policy, rebuilds and executes the installed mechanism and compares the complete resulting certificate bytes. Secure Hash Algorithm 256-bit (SHA-256) digests commit bytes, not physical truth or trust-root authority.

The checker first reconstructs immutable namespace objects and checks the complete typed composition. It resolves the selected SIM object by exact identifier and local digest. The SIM payload must bind `isolation_evidence_digest` to the selected retained finite model. The finite-isolation mechanism checks all reachable outcomes, including nondeterminism and cycles. Contradictory bytes, kinds, references or explicit boundary effects FAIL; missing transition coverage and unsupported effect semantics remain UNKNOWN. A checker ceiling reached before candidate bytes can be safely captured raises `Unavailable` (uncertainty) and issues no certificate; it cannot honestly replay an omitted oversized input as though those bytes had been retained. A falsely incomplete model can still PASS relative to its declaration, so independent physical observation is a separate obligation.

Before collection serialization, the builder captures exact built-in namespace fields, rejects active scalar subclasses, and charges the canonical encoded reference bytes used by composition replay. The emitted collection and request are derived from that checked snapshot, so a caller changing a frozen record during serialization cannot rebind the request. This is a local input-capture invariant, not an arbitrary Python callback sandbox or a guarantee against concurrent mutation outside the selected capture boundary.

The mechanism is admitted by a caller-selected external policy naming an exact installed implementation digest and trust-root labels. Labels do not authenticate their own issuer. Built-in replay does not execute submitted plugins, sandbox arbitrary Python, or infer complete dependency closure. A changed code/specification dependency changes the mechanism digest and requires policy readmission. This candidate provides no general current-object profile aggregator or coverage for the other objects or tiers.
