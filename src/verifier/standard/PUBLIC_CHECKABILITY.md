# Experimental public checkability admission, version 1

JavaScript Object Notation (JSON); Secure Hash Algorithm 256-bit (SHA-256);
directed acyclic graph (DAG); identifier (ID);
hash-based message authentication code (HMAC);
Unicode Transformation Format, 8-bit (UTF-8);
American Standard Code for Information Interchange (ASCII);
application programming interface (API).


Experimental bounded public-checkability contract. Full polish, publication,
human acceptance and release qualification remain separate.

## Exact proposition and retained public witness

For the independently selected finite required certificate DAG node contexts, the
complete carried public artifact byte inventory, exact native requests, exact
native policies, selected namespace records, profiles, claims and prerequisite
edges permit an outsider to reconstruct the retained native witnesses and obtain
the same installed native replay and qualified prerequisite results, without any
secret policy key or privileged witness source. Authenticated disclosure admission
under independently selected public keys, roles and time applies to that exact
package. PASS describes this bounded checkability proposition only.

No producer `complete=true`, certificate count, slot label, success flag, signature,
hash, prior assessment, author callback or self-selected verifier establishes this
proposition. One objective is one semantic-version/coordinate/proposition/scope
claim, not one certificate per tier or per slot. Actual public retrieval,
publication, human consent, institutional authority, clock authenticity,
cryptographic backend qualification, model correctness and overall safety remain
separate. The wrapper never issues a polished artifact.

This adapter does not attest already-loaded Python code, the machine, cryptographic
backend, operator configuration or import environment. Its source digest reads
selected installed source files under a trusted fixed host-process assumption;
live file hashes are not evidence that already-loaded code matches those files.
The assessment explicitly records
`runtime_provenance=TRUSTED_FIXED_HOST_PROCESS_REQUIRED;NOT_ATTESTED_BY_SOURCE_HASH`.
The operator must independently qualify and bind the fixed installation/source/tree/wheel/
import origins/backend/current authenticated configuration and epoch channel before
an issuer relies on these results. No producer callback or source hash bootstraps
that trust. Exact issuer policy_domain/policy_epoch must match the authenticated
host ledger selection; these are issuer bindings, not new OBJECT-1.1 claims.

An issuer must independently compile and admit the complete applicable inventory:
all 234 slot positions, every applicable internal `.m` objective, object instance,
interaction, relation, applicability decision and prerequisite. No denominator,
application profile or certificate inventory is derived merely from the installed
route catalog. An unsupported objective or unknown required certificate is
UNKNOWN. The existing native DAG is finite profile closure, not this complete
normative inventory. No new public-checkability PASS waives an existing native FAIL,
UNKNOWN, missing promotion evidence, required human acceptance or authority hold.

## Versioned wire and external selection

Proposed API `verifier.runtime.public_checkability`:

```
assess_public_checkability(bundle_bytes, *, request_bytes,
    disclosure_policy_bytes, disclosure_evidence_bytes, evaluation_time)
recheck_public_checkability(assessment_bytes, bundle_bytes, **external_selection)
mechanism_digest()
node_contexts(dependency, policy)  # formatting only; no admission
disclosure_subject(request_bytes) # formatting only; no admission
disclosure_policy_terms_digest(policy)
```

New wrapper records and native DAG records use UTF-8 JSON with sorted keys, compact separators, ASCII escapes and
no nonfinite numbers, matching existing native canonical_bytes. This differs from
the ensure_ascii=False convention for editorial proposed-text pins. Existing public
consent signing/envelope digest bytes retain their separately defined
ensure_ascii=False format; no signature is recanonicalized under the new wrapper.
The wrapper retains the exact public-consent evidence bytes and calls its actual
existing authenticator. Duplicate
keys, type coercions, unexpected fields, noncanonical base64 and path aliases are
refused. Bounds are checked before callbacks; no candidate-selected file path,
module, callback or ambient key lookup is accepted.

Fresh assessment screens each present admitted request and disclosure input before
missing companions or current source availability. Request grammar, digest syntax,
fixed public audience/purpose, and sorted unique required-node grammar are local
checks. A present disclosure policy is checked against the exact selected terms and
derived-subject singleton binding whenever the request is present; a present
evidence record is checked for its closed wrapper grammar and plain grant list.
Present malformed/substituted inputs refuse even when a companion is absent. The
exact carried native bundle/policy pins, artifact inventory and node contexts are
also compared before reading the current adapter source digest. No such local
screen authenticates keys, signatures, grant effects, configured authority or
native truth, and it supplies no missing policy, witness or proof protocol.
The actual source equality, disclosure authenticator/rechecker and available native
gate remain required before PASS. The initial whole-transport overbound capture
rule below and the separately guarded historical recheck retain their meanings.

Before any submitted-input hash, inspect the plain byte type and transport cap of
ALL bundle/request/disclosure-policy/disclosure-evidence inputs. Foreign built-ins
refuse before invoking their length or methods. Overbound bytes are never hashed or
retained; admitted bounded siblings can still identify a known historical selection
contradiction. None is explicitly captured absence, not evidence. Without an
established local contradiction, a missing required bundle/request or disclosure
input remains UNKNOWN. `input_digests` contains hashes
only of admitted bounded present inputs, with null for absence or unretained bytes.
`input_capture` is BOUNDED_CAPTURED when all transports were admitted (including
explicit absence), INCOMPLETE_BOUND for any overbound input, or NOT_CAPTURED when
admission did not finish. An incomplete captured report cannot assert exact replay
of bytes it never retained or hashed.

`verifier-public-checkability-bundle-1` carries exactly:

* `schema_version`;
* `dependency_bundle_base64`: exact existing certificate DAG bundle bytes;
* `dependency_policy_base64`: exact externally selected existing DAG policy bytes;
* `artifact_files`: sorted unique `{path, base64}` snapshot-relative file records.

`verifier-public-checkability-request-1`, independently retained by the caller,
contains exactly schema_version, installed new mechanism_digest,
dependency_bundle_digest, dependency_policy_digest, artifact_inventory_digest,
required_nodes, disclosure_policy_terms_digest and disclosure. Digest fields are
`sha256:` plus lowercase 64-hex SHA-256. Artifact inventory is the existing DAG hash
of the sorted complete `{path,digest,size_bytes}` set; extra files change the
inventory as well as omitted files. Bundle/policy exact bytes are independently
pinned, not inferred as trusted selection from the carried package.

`required_nodes` is the sorted exact native node set, with no duplicate, omission,
reordering or extra. Each record contains exactly node_id, mode, context_digest,
proof_protocol_id and proof_statement_digest. Public-native mode requires the two
proof fields to be null. Confidential mode requires a named protocol and exact
statement digest but cannot PASS in this version. Disclosure contains exactly
actor_id, observer_id=`PUBLIC`, purpose=`PUBLIC_CHECKABILITY`. These fixed strings
introduce a new explicitly selected audience and operation; they do not migrate
existing PUBLISH, ISSUE or inventory-admission grants.

`verifier-public-checkability-node-context-1` binds the full exact native node
(certificate path/digest, native request, native checker policy, replay version,
facets and artifacts), exact selected object record and object selection, complete
selected profile, exact selected claim including semantic/objective/proposition,
scope/assumptions/dependencies, all sorted declared DAG edges, and exact dependency
policy digest. Shared namespace identity cannot substitute a changed instruction,
context, policy, output or artifact revision if that revision is part of the
selected native request/record. Any applicable external revision absent from the
native proposition still needs an explicit versioned objective; it is not implied
by a hash.

## Acyclic authenticated disclosure

The new operation is `DISCLOSE_PUBLIC_CHECKABILITY_WITNESS`. Its canonical subject
`verifier-public-checkability-disclosure-subject-1` contains operation,
request_digest, dependency_bundle_digest, dependency_policy_digest,
artifact_inventory_digest, installed adapter mechanism_digest,
disclosure_policy_terms_digest, and the fixed
`EXACT_SINGLE_OBJECT_DERIVED_SUBJECT` binding rule. The request includes all exact
required node contexts, public actor/audience/purpose and immutable input pins.

Policy authority terms are the entire exact `verifier-consent-public-policy-1`
record excluding only artifact_bindings. The external request pins these terms.
The actual separately selected policy must contain exactly one artifact binding:
`[["OBJECT", raw_sha256_of_disclosure_subject]]`. This is a deterministic complete
policy reconstruction, avoiding a cycle in which a policy hash includes its own
signed artifact hash. The full actual policy byte digest is retained in the
assessment. Public grants/revocation envelopes sign the derived subject digest;
their bytes and the actual public consent receipt/replay are separately bound in
the assessment, not in the subject that their own signatures authenticate.

Use actual existing `evaluate_public_consent` and `recheck_public_consent`, with
`ConsentContext("OBJECT", raw_subject_digest, operation, externally_selected_actor,
"PUBLIC", "PUBLIC_CHECKABILITY", externally_selected_evaluation_time)`. Public
root/revocation roles remain separately configured. Require consent PASS,
replay_status REPRODUCED and admission_status PASS. REPRODUCED UNKNOWN or REJECTED
does not pass. A well-formed hash or admitted Ed25519 encoding is not signature
verification; actual Ed25519 verification is required. A known forged signature,
wrong artifact, audience, purpose, key role, actor, denial, revoked ancestor or
expired grant is a refusal. Missing backend, unknown key, missing trusted time or
stale/missing revocation evidence is UNKNOWN.

Evaluation time is an external argument, not a producer timestamp. It is retained
in the assessment and used for authenticated interval/freshness checks. Exact
historical replay reselects the same time; it makes no present authority claim.
Present issuance requires a fresh assessment with current independently admitted
time and revocation evidence. No cached PASS fallback is permitted.

This authenticates configured-key statements only. The holder's real authority,
actual human consent, public-policy distribution and clock trust are external
issuance dependencies. A disclosure permission must cover the full disclosed
certificate/policy/sidecar bytes; namespace `<kind>-6.7` alone does not do so.
HMAC inventory authority is a different operation and trust model. Its secrets
must never enter this public witness or be treated as a public proof.

## Installed public-native capability in this proposal

The only proposed initial adapter is exact semantic version
`verifier-current-object-obligations-1`, objective `OBJECT-1.1`. Its five-field
checker policy contains schema, mechanism ID/digest, bounded trust-root labels and
max certificate bytes. Labels are not private keys or authenticated authority.
Its certificate retains exactly one base64 namespace-record witness keyed by the
selected evidence_ref. The adapter reconstructs those exact bytes, verifies their
digest, then invokes the existing native certificate DAG checker. Native replay
independently verifies the full policy/request/proposition/source digest, subject
and kind, generic facets/address, bounds and every rebuilt certificate byte.

Every required node must have an installed source-grounded public capability;
there is no producer-selected completeness flag or generic secret-name blacklist.
Other routes initially report PUBLIC_NATIVE_ADAPTER_UNAVAILABLE and fence native
callbacks for the whole package. Missing retained certificate/witness and capacity
exhaustion are UNKNOWN; known substitution/malformed witness is a refusal. This
deliberately prevents a claim that the generic route catalog is public-proof
coverage. Expanding the registry requires full named source/spec reads, a precise
retained-input closure, source/mechanism pins, secret-free policy schema and
positive/adversarial actual replay for each route and every transitive child.

After disclosure admission and full adapter availability, invoke actual
`assess_certificate_dependencies` with exact selected policy bytes and complete
artifact snapshot. Require every required node's qualified_status PASS and overall
native status PASS. Direct PASS without prerequisite PASS is insufficient. Native
FAIL remains FAIL. Native unavailable/cancelled/bounded UNKNOWN remains UNKNOWN.
Existing DAG aggregate accounting and all exact profile/typed edge rules remain
unchanged. Unsupported sibling nodes fence this wrapper; the issuer must combine
its separately run native gate so an existing native FAIL is never erased by this
wrapper's UNKNOWN.

The private code is concrete integration scaffolding, not validated runtime. Its
OBJECT-1.1 fixture uses real native builders and real Ed25519 signatures in proposed
tests; neither fixture nor cryptographic backend has been run in this task.

## Confidential witness protocol is unavailable

No confidential proof protocol is installed by this proposal. Its mode remains
CONFIDENTIAL_PROOF_VERIFIER_UNAVAILABLE, never converted into public retained
replay or a digest/signature argument. The v1 bundle is not a confidential transport:
it carries public native DAG records. Withheld private witnesses must stay outside
it. A confidential adapter needs a separately versioned public statement format.

A future named proof admission requires actual checked proof bytes, named proof
system/version and assumptions, exact compiled program/circuit and predicate
digests, verification-key/parameter digests and provenance, complete public inputs
and output, hiding witness commitments and their opening/relation semantics,
selected certificate/native request/policy/context/artifact inventory bindings,
limits, and an actual installed verifier with independently selected metadata.
The verifier must prove the same bounded native predicate and prerequisite claims,
not merely possession of some witness or a weakened predicate. Omitted context,
substituted output/program/input/key, vacuous constraints, malformed proof,
wrong commitment, unavailable backend, cancellation and exhaustion need explicit
adversarial outcomes. No such evidence has been established in the inspected C20
surfaces. Existence of arbitrary cryptography elsewhere is not denied.

## Outcome and resource semantics

PASS applies only to exact finite public checkability with admitted disclosure.
FAIL records a known malformed/substituted/refuted input or authenticated refusal.
UNKNOWN means a required input, checker, proof protocol, capability, disclosure
admission or bound is unavailable. Cancellation yields UNKNOWN if caught before
termination; KeyboardInterrupt/SystemExit or external termination produces no
assessment. Existing observed FAILs cannot be converted to a pass by later bounds.
The assessment retains fixed reason codes and digests, not witness data, keys,
exception text or producer explanations. It always reports polished_artifact=false,
inventory_completeness/human_acceptance/public_availability/claim_correctness/
overall_safety NOT_ESTABLISHED and publication NOT_PERFORMED.

Proposed v1 caps: 112 MiB outer base64 package; 8 MiB request/native bundle/native
policy each; 1 MiB disclosure policy/evidence each; 1024 files/64 MiB total decoded
artifact bytes; 512 nodes/4096 edges; structural depth48/100000 visits per parsed
record, numeric token1234 digits/integer4096 bits; 2 MiB retained assessment.
Node-context canonical hashing separately charges 64 MiB cumulatively; the policy
digest and sorted edges are computed once. Shared profile/witness bytes receive no
discount when each node context or native replay checks them again.
Existing native DAG still charges 64 MiB cumulative replay. This protocol needs a
new capacity version for complete inventories beyond those caps; C20 polish-v2
capacity does not silently enlarge native DAG or this protocol. These are finite
representation/work allowances, not benchmarked peak RSS, elapsed time or machine
safety guarantees. Base64 plus decoded buffers can coexist in memory; measure peak
memory under authorized qualification before deployment.

Historical recheck compares exact canonical assessment bytes after actual replay.
It first validates the exact retained assessment field set/claim boundary and its
own digest, then compares every available admitted current input against each
known retained input digest and compares an available selected historical clock.
Known changed bytes or time FAIL before generic missing-input/backend/proof/capacity
UNKNOWN classification. A changed valid package cannot become merely UNAVAILABLE
because the newly selected package has an unsupported proof or missing checker.
Missing previously retained input or never fully captured overbound input is
UNAVAILABLE when no known contradiction has been established. No overbound input is
hashed during recheck. Immutable fixed diagnostics may still have their own digest;
they are not input commitments.
REPRODUCED with public_checkability_status UNKNOWN/FAIL retains that status. A
previous positive assessment with an unavailable current checker is UNAVAILABLE,
not proof of historical forgery. Substitution is FAIL. No replay result constitutes
current authority, actual publication or new human acceptance.
