# Core version 2 release scope

Verifier Standard (VSTD); work in progress (WIP).

Core release target: `2.0.0`.
Core release scope: `verifier-core-release-scope-1`.
Core current-object semantics: `verifier-current-object-obligations-1`.
Included extension: `verifier-corrigibility-extension-wip-1`.
Extension selection schema: `verifier-corrigibility-extension-selection-1`.
Extension status: `WIP`.
Extension completion: `UNKNOWN`.
Extension core gate credit: `NONE`.

The native core consists of the retained 26 `ObjectKind` values, each under the
nine core tiers named by [META_TIERS.md](META_TIERS.md). The installed extensible
namespace contains 38 kinds: those 26 plus 12 accumulating consequential roles.
Those roles retain their own applicability obligations and do not change the
234-slot native-core denominator. The included corrigibility extension is a
separate evolving cross-kind work in progress (WIP) for the retained 26 kinds. It
is not a tenth core tier and supplies no core gate credit.

The core can be finalized independently of complete corrigibility. This scope is
a release boundary, not a certificate, a declaration of complete applicability,
or evidence that a candidate is ready. Development version `2.0.0` remains an
unreleased candidate until separately authorized finalization and promotion.

Core release qualification still requires exact source and artifact bindings,
core polish and its independently selected required certificate instances,
complete descriptions, required source explanation predicates, applicable tests,
optional dependency checks, cross-platform release reproduction, current hosted
promotion evidence and trusted human acceptance. An unknown required core
obligation blocks core clearance. `TIME.md` remains the independent live-
contradiction annunciator and must be `CLEAR` for publication; ordinary unfinished
work and the WIP extension remain explicit release evidence rather than a semantic
conflict.

The source archive and source distribution retain the corrigibility
implementation, tests and these specifications as WIP. The wheel retains its
runtime implementation and specifications. Inclusion establishes no extension
completion, production authority, complete effect coverage, observer independence,
application polish, or overall safety. Packaged WIP source still participates in
integrity, description, source explanation applicability, dependency and
adversarial checks. Required source obligations are not removed just because the
source belongs to the extension.

The core nine-tier inventory and parser retain their existing coordinates. This
scope selects no extension-wide native semantic family or progression schema. The
retained historical ten-rank application/progression route remains explicitly
selected by `verifier-application-release-selection-1`,
`verifier-current-ten-tier-progression-1` and
`verifier-ten-tier-progression-selection-1`, including its
`COMPLETE_CORRIGIBILITY` full gate. The additive opt-in ten-tier native-object
family `verifier-current-ten-tier-object-obligations-1` retains only its registered
finite `VERIFIER-6.1` and `VERIFIER-10.1` routes. Neither retained surface selects,
implements or completes the cross-kind extension, and neither supplies core or
extension-wide gate credit. Historical certificates are not silently converted.

The release builder and distribution verifier must require the declarations above
for a final `2.0.0` artifact. They reject absent or altered WIP status, completion,
selection-schema and core-credit declarations. Existing artifact checks require
this specification to be packaged byte-identically from the selected source. Those
checks establish the declared packaging boundary; they do not establish the truth
of core polish or confer promotion authority.

The extension's research boundary is documented in
[CORRIGIBILITY_RESEARCH.md](CORRIGIBILITY_RESEARCH.md). The distinct retained
ten-rank and additive ten-tier-native contracts are mapped in
[SEMANTIC_CONTRACT_SELECTION.md](SEMANTIC_CONTRACT_SELECTION.md).
