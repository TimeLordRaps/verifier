# Current RECEIPT-9.1 selected hash chain

This is one dimensionless, bounded security objective in the current Verifier Standard (VSTD) object hierarchy, semantic version `verifier-current-object-obligations-1`. It does not reuse a historical numbered-profile meaning. It does not complete RECEIPT tier 9 or the RECEIPT object profile.

## Selected proposition and trust boundary

Reconstruction must reproduce the entire retained namespace record byte-for-byte in canonical form. Constructor normalization cannot admit malformed operand values as a selected empty operand map. A valid empty map remains admissible to this standalone security objective; typed-composition closure is checked separately.

For an externally selected `RECEIPT` namespace-object identifier and record digest, domain, genesis digest, first sequence and tip digest, retained canonical evidence reconstructs that exact object and contains a nonempty contiguous sequence of exact receipt byte strings. The checker verifies the object's four chain-anchor payload fields, then recomputes each domain-separated link from the exact bytes and reaches precisely the selected tip. A receipt byte string is opaque; this objective does not parse or validate a receipt dialect. The namespace object's operands are retained and digest-bound, but this security objective does not resolve them or establish typed-composition closure.

The selector must retain the `RECEIPT` object identifier and digest, domain, genesis, first sequence, tip, evidence reference, policy and trust-root decision **outside** the candidate certificate. The policy's trust-root strings are labels, not proof of who selected them. A builder can format a request, but a builder-produced tip selected by the same adversary supplies no external security anchor. The Secure Hash Algorithm 256-bit (SHA-256) binding assumes collision resistance; the checker does not prove it. No digital-signature verification, issuer authenticity, non-repudiation, trusted time, availability, absence of earlier or later receipts, or full history consistency is established. Publication of retained bytes requires separate authorization.

Each link hashes canonical JavaScript Object Notation (JSON) with schema `verifier-receipt-chain-link-1`, selected domain, zero-based or higher sequence, previous link digest and SHA-256 digest of the exact receipt bytes. The selected genesis is the first previous digest. Sequence numbers start at the selected first sequence and increase by one. The evidence is a canonical JSON document with schema `verifier-receipt-chain-evidence-1`, exact domain, a `receipt_object` namespace record and a nonempty `entries` array; every entry has exactly a `sequence` integer and canonical base64 `receipt_base64` text. The `RECEIPT` object's payload has exactly `chain_domain`, `chain_genesis_digest`, `chain_first_sequence` and `chain_tip_digest`. A digest can identify a chain only under the selected domain and position rules.

An independently selected request fixes the current coordinate `RECEIPT-9.1`, proposition digest, `RECEIPT` object identifier and digest, domain, genesis, first sequence, tip, exact evidence reference, policy digest, maximum entry count and evidence-byte budget. The policy fixes the installed checker/specification digest, bounded certificate size and named trust roots. The certificate retains the evidence and evaluation for offline replay. Recheck rejects substituted requests, policies, mechanisms, evidence or result bytes, even if an attacker recomputes the envelope digest. The mechanism uses the shared content-addressed evidence store and verification session. Source/specification changes require a newly selected policy.

PASS means only the selected `RECEIPT` record and finite interval of retained bytes reach the selected tip. A noncanonical or malformed evidence document, duplicate JSON key, wrong object kind or anchor, gap, wrong domain, reordered/omitted item or wrong tip is FAIL when its exact retained bytes are selected. Missing evidence and exhausted finite checker bounds are UNKNOWN. A malformed or substituted selection/policy/certificate refuses construction or replay without promoting a verdict. The current ceilings are 64 entries, 256 kibibytes (KiB; 1024 bytes each) per receipt, 1 mebibyte (MiB; 1024 KiB) retained evidence and 2 MiB certificate. These limits bound only the local checker interface, not arbitrary host callbacks or downstream consumers.
