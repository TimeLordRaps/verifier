# Selected finite Verifier replacement

Verifier Standard (VSTD); JavaScript Object Notation (JSON); Secure Hash Algorithm
256-bit (SHA-256); Unicode Transformation Format, 8-bit (UTF-8). Ed25519 is the
Edwards-curve digital signature algorithm with a 255-bit field. This experimental
direct-module contract selects `VERIFIER-10.1` only under
`verifier-current-ten-tier-object-obligations-1`. Historic nine-tier coordinates
retain their meanings. This predicate does not supply another prerequisite.

The proposition is finite observed revocation, empty drain, one separately
authorized successor, actual stale callback refusal and successor callback entry
inside one selected local permission-slot callback boundary. The consumer chooses
the subject, collection, operation, boundary, old and successor tuples, exact
retained capture, ordered trace, terminal census, effect inventory, revocation
view and cutoff, source closure, admission roots and evidence before replay.
The checker never invokes a callback or repeats an effect.

`PASS` establishes this finite proposition under those admitted roots. It does
not establish whole application corrigibility, authority correctness, actual
executed instruction attestation, availability, BURN erasure, arbitrary external
effects, context consumption, trusted clock freshness, live revocation, human
acceptance, production admission or public disclosure authority. Effects in
preparation, grant verifiers, observer setup and code outside the selected
registered callback boundary are excluded. They remain separate qualification
obligations. Session and process identifiers are exact selected declarations;
portable replay does not authenticate the original operating system process.

## Closed selection and retained bytes

The native module is `verifier.domains.contracts.verifier_replacement`. Its
mechanism identifier is `verifier.ten-tier.verifier.selected-replacement.1`.
The closed wire identifiers are
`verifier-ten-tier-verifier-replacement-request-1`,
`verifier-ten-tier-verifier-replacement-policy-1`,
`verifier-ten-tier-verifier-replacement-evidence-1` and
`verifier-ten-tier-verifier-replacement-certificate-1`.
The selector, context, admission, attestation, authority, observer and execution
closure identifiers use the corresponding `selection-1`, `context-1`,
`admission-1`, `attestation-1`, `authority-1`, `observer-1` and
`execution-closure-1` suffixes. Unknown or missing record fields are refused.

The request binds the explicit semantic version, coordinate, proposition,
VERIFIER kind, subject identifier, object and collection digests, operation and
boundary identifiers, initial and successor tuples, source closure digest,
capture digest, trace digest, terminal sequence, terminal census digest,
revocation cutoff and view digest, effect inventory, candidate evidence digest,
policy digest, evidence byte allowance and explicit cancellation observation.
Each tuple contains artifact, instruction, policy and context digests, session,
process and generation. Generations are plain integers from 1 to `2**63 - 1`;
the successor must be exactly the next generation and the same selected process.

Each selected effect row contains invocation identifier, effect identifier,
effect digest and exact tuple digest. Rows are sorted by distinct invocation
identifier. Identifiers contain at most 256 UTF-8 octets and no control characters.
The evidence ceiling is eight mebibytes; the certificate ceiling is sixteen
mebibytes. Larger host captures cannot be admitted by this bounded native route.
The parser admits only exact plain null, boolean, bounded integer, string, list
and string-keyed map values. Duplicate JSON keys, foreign primitive subclasses,
floating point values and unknown record fields are refused. Decoding is bounded
by 48 nested containers, 150,000 primitive values and 16,384 list items.

Evidence retains the original local host capture as canonical base64, plus an
addressed base64 map containing exact subject and collection bytes, old and new
artifact, instruction, policy and context bytes, permissions, grant evidence,
revocation views, selected effect bytes and source closure bytes. Missing selected
bytes yield `UNKNOWN`; every supplied addressed payload is rehashed. The selected
VERIFIER subject is reconstructed with its namespace identity and exact bytes.
Collection bytes are retained by exact commitment; this mechanism does not
independently establish complete collection membership or applicability.

Typed context bytes are canonical closed records containing the context version,
revision digest and TIME, TOKEN, ENV, HARDWARE and SPACE byte references. Each
facet retains canonical `{kind, record}` bytes with its exact kind; the revision
bytes are also retained. This establishes selected typed byte association, not
truth of every context facet or proof that executing code consumed it.

The canonical execution closure contains its version and exact executor,
observer, harness and native mechanism digests. The native digest must equal the
consumer policy's installed checker pin, and its canonical source manifest bytes
are retained. The installed pin commits this native module, its packaged
specification, the local permission-slot module and specification, ten-tier
progression specification and the exact used core parsing, certificate, evidence,
namespace and selection primitives. It excludes the dispatch registry to avoid
recursive registration. Exact selected executor, observer and harness source bytes
are retained; their execution and admission remain external dependencies.

## Explicit authority and observer admission

The policy selects sorted distinct trust-root labels, the native mechanism pin,
certificate allowance, one admission-root key identifier and public key, exact
authority and observer key maps, and exact full authority and observer admission
record digests. Key maps contain one to sixteen exact identifiers and canonical
32-byte public keys. The installed standard-library key screen refuses known
small-order and noncanonical encodings, and its exact source is in the mechanism
commitment. This screen does not prove full subgroup membership, key custody or
authority; the optional backend still verifies every signature. All keys and
admission pins are external consumer choices.
The checker supplies no default production authority or self-selected issuer.

An admission record is an attestation envelope with version, key identifier,
payload and canonical 64-byte signature. Its full bytes must reproduce the
externally selected admission digest. The admission root signs the exact key
map, subject, object, collection, old and successor tuple digests, operation,
boundary, source closure and purpose. The authority purpose is `grant-and-revoke`;
the observer purpose is `observe-complete-effect-census`. Signing bytes are the
literal `verifier-ten-tier-verifier-replacement-signature-1`, a zero octet and
canonical payload bytes. The optional cryptography backend is imported lazily.
Signature validity authenticates these bytes under the selected key; it does
not independently justify the root, key custody or production permission.

Authority statements sign each exact committed grant decision and the selected
revocation statement. They bind the same subject, collection, operation, boundary,
capture and execution closure. Grant decisions retain status, complete grant and
precommit epoch. Grants retain exact selection, authority, permission digest,
revocation view digest, evidence digest, nonce and initial or successor purpose.
The commit epoch must be the decision epoch plus one. Nonces cannot repeat.
The authority whose old active grant was revoked cannot grant its successor.
The revocation statement binds the old tuple, selected cutoff epoch, exact view
digest and revoked authority. The successor grant must use the selected view.
View freshness here means exact externally selected bytes and cutoff; no clock
or universal challenge-consumption service is inferred. Opaque delegation and
grant-evidence truth remain the admitted external authority's obligation.

The observer signs exact subject and collection bindings, operation, boundary,
capture, trace, terminal census, source closure, selected effect inventory,
per-effect attempt, entry and exit counts, and an explicit complete-coverage flag.
Counts are reproduced from the ordered retained trace and independently selected
observer's retained actual local observations. Incomplete coverage or missing
actual stale attempt yields `UNKNOWN`. An asserted complete census that omits a
known registered effect or contradicts a known entry yields `FAIL`. A partial
census may omit unknown coverage, but cannot contradict observed entries.

## Replay and outcomes

The independent interpreter registers exact queued tickets, one callback attempt
per invocation, balanced actual entry and exit or refusal, atomic grant epochs,
revocation, empty observed drain, frozen successor intent and one successor.
Entry requires the active exact tuple, permission and epoch after the observer's
final boundary check. Old entry before revocation may finish afterward; new
entry under stale or revoked authority fails. Events carry current host epoch
even when a stale ticket carries its earlier epoch. Entry observations match exact
tickets rather than observation list order, so nested completion is permitted.
Uncommitted grant decisions after failed preparation cannot imply an activation.
Cancelled attempts can leave no completion event because the host cleans its
inflight count in a finally block; missing lifecycle coverage remains `UNKNOWN`.

Visible tuple, byte, signature, source, nonce, cutoff, purpose, lifecycle or census
contradictions and retained prior `FAIL` dominate later missing evidence,
cancellation and unavailable dependencies. Missing capture, admitted authority,
observer coverage, exact retained bytes, usable signature backend or complete
lifecycle yields `UNKNOWN`. Replay never upgrades an uncertain observation.

Certificates bind `BoundProposition`, an `EvidenceStore` and `VerificationSession`
to the exact selected request and retained evidence. The portable rechecker takes
the same explicit request and policy, rebuilds the certificate and requires exact
byte reproduction. An unavailable checking dependency may return `UNKNOWN` with
`replay_status=UNAVAILABLE`, preserving immutable claim boundaries. It cannot
turn a carried failure into a reproduced passing verdict. Successful finite
replay has `replay_status=REPRODUCED`; full corrigibility admission remains
`UNKNOWN`, and all excluded claims remain `NOT_ESTABLISHED`.

Local positive controls use actual permission-slot invocation, entry, drain and
capture with explicitly selected fixture authority, observer and admission keys.
Such controls establish bounded checker behavior under fixture policy, not real
operation witnesses, production admission or human acceptance. Required real
operation-instance evidence and admissibility choices remain independent gates.
