# Exact declared namespace requirements compiler

Verifier Standard (VSTD); directed acyclic graph (DAG); JavaScript Object
Notation (JSON); Secure Hash Algorithm 256-bit (SHA-256); identifier (ID).

This additive version-1 mechanism compiles requirements before certificate outcomes.
It does not change retained facet, inventory, polish or certificate DAG contracts.
Direct module: `verifier.domains.contracts.application_requirements`.

`derive_current_application_requirements(source_scope_bytes, collection_bytes,
selection_bytes, expected_compiler_policy_bytes=...)` returns
`verifier-current-application-obligations-1`. Its rechecker requires externally
selected expected mechanism and manifest digests, the same original exact inputs,
and byte-identical independently reconstructed canonical output. No callback can
supply completeness or authority. All accepted inputs are immutable canonical JSON
bytes; duplicate/additional fields refuse admission. Exact source/input/mechanism
bindings are retained for replayable FAIL and UNKNOWN as well as scoped PASS.
Recheck bounds the carried manifest and original immutable transport inputs and
validates the independently selected output/mechanism commitments before installed
source reconstruction. Changed original input commitments, including compiler policy,
are FAIL/REJECTED before a source outage can obscure them. A malformed bounded known
binding or available reconstructed byte mismatch remains FAIL/REJECTED. Over-bound
replay input or unavailable reconstruction returns UNKNOWN/UNAVAILABLE and never
REPRODUCED; an observed current FAIL remains FAIL. Unavailable replay retains actual
captured current bindings and distinguishes expected_manifest_digest from the current
observed_manifest_digest. It never carries forward a previous PASS as reproduced.

Two profiles are recognized: `retained-namespace-structure-1` and
`full-current-application-1`. Only the first has an installed closed finite
proposition scope: the four generic structural facets specified by
CURRENT_OBJECT_FACETS.md and the independently specified typed composition facet
in CURRENT_TYPED_FACETS.md, for every supplied namespace object. These bind opaque
payload bytes; they do not establish payload scientific/domain meaning. Source
language `CANONICAL_NAMESPACE_COLLECTION_1` is exactly canonical
`verifier-polish-object-collection-1` JSON, not arbitrary program semantics.

A source scope has exactly schema_version, scope_id, revision, source_units,
normative_families, semantic_mappings, interaction_generators, census_evidence.
Each source unit has unit_id, language, bytes_b64, bytes_digest. Standard base64
must decode and re-encode identically, including padding bits; exact byte digests
must match. Source unit IDs and record origins are unique. The complete source
record union must equal the independently selected namespace collection exactly.
The census_evidence object has source_member_census_digest; this is compared to
the complete installed frontend's reconstructed field census, never trusted as
an author completeness claim. Source authority and source truth remain external.

Namespace paths include every retained container/scalar, role/ordered target and
array position; strings and integer path indices stay distinct. Each source and
namespace facet binds exact record/value digests. Five semantic facets per object
retain their exact many-to-many source/namespace origins. The installed interaction
generator enumerates every declared operand occurrence, its role, ordered index,
target ID and target record digest. Typed composition covers these relationships
inline; they do not invent native child-certificate edges or scientific interactions.
Unsupported application mappings or interaction generators remain UNKNOWN.

The compiler explicitly retains all 26 kinds times nine tiers in
normative_family_census. Each cell has family_id, semantic_version,
represented_kind, tier, scope_kind, selected_scope_members,
selected_scope_family_closure, full_family_members and full_family_closure.
For tier1, the selected structural scope has its generic and kind-specific
structural predicates. Other tiers are outside this narrow selected scope.
Every full_family_members is null and every full_family_closure is UNKNOWN.
No slot receives an invented objective or certificate. `all.m` means the exact
closed member set of a selected semantic family, never `1..max_seen`, one per
tier, all registered runtime entries or a per-kind prefix filter. No complete
full application family is installed; requests for unsupported families retain
localized UNKNOWN. Full profile always retains the 234 family holes and every
represented object's nine unresolved application cells. It cannot PASS.

The selection fields are schema_version, application_profile_id,
application_profile_version, root_id, semantic_version, source_scope_digest,
collection_bytes_digest, collection_digest, selectors, native_intents. Native
intents contain object_id, coordinate, request, checker_policy. They supply exact
consumer-selected intent to requirements already derived without certificates.
Missing intent leaves REQUIRED intact with UNKNOWN binding. Extra intent outside
the closed structural scope is a contradiction; an unsupported full-application
intent remains UNKNOWN applicability/context rather than becoming an obligation.
Each requirement has exact proposition, subject revision, rule/origin/context
commitments. Requests and policies undergo the actual fixed native schema/policy
validators; same-label substitutions cannot bind another request or native context.

The external compiler policy fields are schema_version, mechanism_digest,
source_scope_digest, collection_bytes_digest, selection_digest,
installed_rule_set_digest, normative_family_set_digest, allowed_frontend_digests,
admitted_rule_digests, limits. The rule set and frontend are fixed installed
authored functions, source-pinned to their actual normative/native/core bytes.
New byte/spec revisions require fresh authored review and independent selection.
Rule admission/pins do not authenticate their issuer. No candidate rule extractor,
import path, command, schema outcome or positive flag is executed/trusted.

The output retains separate source/namespace/family/applicability/interaction/
projection/consumer status fields, exact ledgers, REQUIRED objectives, actual
supported DAGv1 profiles, native projection and unresolved cells. Required-only
profiles retain claim identity and inline assumptions/prerequisites. The two
installed structural producers consume no child certificates, as their fully
read implementations show; their compiled child census is exactly empty, not an
author-selected empty list. Full-application consumer census remains UNKNOWN.
Unsupported native wrappers require authored/pinned selectors before closure;
SIM response's additive link checker does not by itself establish their census.

The compiler additionally binds an installed native-dependency lower-bound digest.
Its fixed portion contains 36 distinct source-observed prerequisite/dependent
coordinate pairs. This includes the separately implemented multi-coordinate
ENV-1.2 to ENV-4.1 and DATA-1.2 to MODEL-3.4 consumers. Its parametric portion
contains 26 object-kind-specific subject-security consumers of RECEIPT-9.1. The
five existing inline completion rules are retained as inline criteria, not cast
as coordinate edges. HYPER-2.3, VERIFIER-3.1, VERIFIER-4.1 and selected
certificate-DAG nodes remain unresolved dynamic families until exact external
selection supplies their instances.

`installed_native_dependency_inventory()` and
`recheck_native_dependency_inventory(...)` are defined in facet_coverage. Exact
replay PASS means only that externally selected canonical inventory bytes equal
the current source-derived lower bound and expected digest. Missing bytes or
unavailable source stay UNKNOWN; digest, row, source or route substitution is
FAIL. The inventory is input to candidate profile review. It does not insert an
edge into a profile, imply applicability, replay a native certificate, close a
family denominator or authenticate completeness. Certificate DAG continues to
instantiate and propagate only exact dependencies in an externally selected
profile. Tier numbers create no edges and a child affects only its authored
direction. `full_source_dependency_inventory` therefore remains UNKNOWN,
`complete_application_profile` remains NOT_SELECTED, and this lower bound is not
an arbitrary release prerequisite.

The reconstructed closure certificate binds the complete exact member-set digests
at every layer, inputs, compiler, resource completion and residuals. Its scoped
conservation PASS is not closure of a larger source/application universe.
`scope_kind` is computed from the separately selected supported profile;
`full_application_status` is always UNKNOWN and `polished` always false. A consumer
seeking full polished/all234 admission MUST require independently reconstructed
full family/member/applicability/interaction/consumer closure and reject this
structural scope, even if its finite compilation status is PASS.

`scope_admission` retains an exact computed admission subject/digest with operation
ADMIT_APPLICATION_REQUIREMENT_SCOPE, inputs, closure certificate, scope and empty
inapplicability list. Authority is NOT_EVALUATED. Issuer must independently replay
a qualified admission mechanism for that exact subject. This mechanism never
supplies N/A waivers, real authority, human acceptance, public checkability,
permission to publish evidence, actual execution or native objective truth.

Limits: each input at most8 mebibytes, objects256, source units64, source/namespace
facets32768 combined, interactions4096, requirements512, charged operations1000000,
output8 mebibytes. Positive selected output allowance is at least8192 bytes for
bounded diagnostics. Typed/native policies retain their own ceilings. Counts and
charge units are dimensionless, bytes are encoded bytes; no elapsed-time or machine
instruction claim is made. Capacity/support/source unavailability yields UNKNOWN;
malformed bounded known bindings yield FAIL. Refused partial/over-bound ledgers
cannot become completion evidence. These finite bounds do not establish complete application meaning, model
correctness, overall safety or human acceptance.

Explicit recursion/overflow checking-capacity exceptions and cancellation alone
do not refute a semantic predicate. They return UNKNOWN and unavailable replay,
retain no carried PASS as reproduced, and preserve independently observed current
FAIL. Bounded structural ValueError refusal and available exact input/output
commitment contradictions remain FAIL. No exception detail supplies evidence.
