# Explicit semantic contract selection

Verifier Standard (VSTD); command-line interface (CLI); application programming
interface (API). Coordinate indices and progression ranks are dimensionless.
A software distribution version, a coordinate spelling, a certificate wire and
an application progression rank are separate selectors.

| Contract | Exact selection | Preserved meaning |
| --- | --- | --- |
| Legacy native computational domains | Closed `verifier-domain-request-1`, `verifier-domain-policy-1`, `verifier-domain-evidence-1`, `verifier-domain-certification-1`; named domain API or certification domain command | Domain adaptation at 5 and disclosure at 6; legacy IDENTITY bearer rules remain fixed. |
| Current nine-tier native objects | Exact externally selected `verifier-current-object-obligations-1`, objective and represented kind; closed native request and policy | Independence 5, Privacy 6, Consent 7, Governance 8, Security 9. Only registered finite predicates are admitted. |
| Retained historical ten-rank application/progression | `verifier-application-release-selection-1`, `verifier-current-ten-tier-progression-1` and `verifier-ten-tier-progression-selection-1` | Cumulative externally selected ranks: Independence 5, Security 6, Privacy 7, Consent 8, Governance 9, Corrigibility 10. Its application route retains the `COMPLETE_CORRIGIBILITY` full gate. A rank is not native semantic admission or current-core credit. |
| Additive opt-in ten-tier native objects | `verifier-current-ten-tier-object-obligations-1`, one exact registered objective/kind pair and its distinct closed request/policy | Separate finite `VERIFIER-6.1` and `VERIFIER-10.1` propositions; no global default, nine-tier parser change, complete-family claim or cross-kind extension credit. Unsupported pairs are refused. |
| Cross-kind corrigibility WIP extension | `verifier-corrigibility-extension-wip-1`; carried by exact `verifier-corrigibility-extension-selection-1` binding | Separate evolving objective across the 26 retained native `ObjectKind` values, not the whole 38-kind extensible namespace. It is not rank 10. Status is WIP, completion is UNKNOWN, and it supplies no core gate credit. No extension-wide native semantic family or progression schema is selected. |

Consumers MUST select the named contract before interpreting a coordinate. The
expected request, policy, installed mechanism and artifact/input bindings come
from the consumer's independent selection, never from the carried certificate.
No missing selector, bare coordinate, historical PASS or software version chooses
a different semantic family. Readers MUST NOT fall back between these contracts
or relabel retained certificate fields to migrate them. An unversioned caller gets
only the API's documented refusal or retained default; it never acquires the
ten-rank route, additive native family or cross-kind extension by inference.

For example, legacy `SIM-5.1` retains mainstay binding while current native
`SIM-5.1` selects finite model-relative confinement. Legacy `HYPER-4.1` retains
Saturation while current native `HYPER-4.1` selects finite declared operand-cone
closure. Legacy bare AGENT identity refusal and current ACTOR-to-ROLE declaration
admission can coexist because their contracts are distinct.

The default current-object catalog retains the nine-tier family. An additional
native family requires an exact separate registry and selection, not wildcard
admission. Nine-tier polish and its historical MetaTier parser MUST reject new
ten-tier native predicates before interpreting their numeric tier. A dependency
graph or ten-rank application path may consume an explicitly registered new
predicate only under its exact semantic, proposition, scope and source bindings.

An explicitly selected overlay may assign an unchanged nine-tier security child
to progression rank 6. That preserves the child's original objective and wire; it
does not issue a new native security certificate by editing an old coordinate.
Complete application applicability, required certificate instances, execution,
public checkability, composed security, complete corrigibility and human acceptance
remain separately required evidence. No selection label supplies that evidence.

Portable application and progression assessment version 2 retains the actual
selection digest, independently supplied expected selection/mechanism digests
(null when absent), and the closed selected root/subject descriptor. Historical
assessment version 1 remains historical under its original source. Readers do not
silently upgrade it or interpret missing identity fields as wildcards.
