# Current capability-token checks

Status: locally admitted experimental current-object routes; production-profile
and full application-mapping authority remain unestablished. Verifier Standard (VSTD); JavaScript Object
Notation (JSON); Secure Hash Algorithm 256-bit (SHA-256).

These explicitly versioned predicates reuse the retained capability-token
mechanics in `DOMAIN_OBLIGATIONS.md` and
`ZIZK_TOKENS.md`. Historical certificates are not relabeled or
accepted as current certificates. New exact evidence, namespace selection,
installed source/specification policy and complete certificate replay are
required. A matching coordinate alone does not select its meaning.

The explicitly selected semantic version is `verifier-current-object-obligations-1`.
`TOKEN-2.1` selects `tenure`: the native inventory and tenure interpreter replay
exactly one declared birth, contiguous epoch folds, permanent retained
revocation, suspended epochs that accrue nothing, and each aging token's
selected head and active-epoch count. The source rows are legacy TOKEN-1.4,
TOKEN-2.1 through 2.3, TOKEN-2.11 and TOKEN-4.2. This is retained lifecycle
arithmetic, not genesis authentication, real survival or actual clock passage.

`TOKEN-3.1` selects `windows`: the native inventory is replayed and lifetime
windows are projected from its exact selected tokens, never from an unrelated
window array. Every finite window must be nonempty and wider than the selected
clock skew. Unbounded expiry is a declared unbounded window and is explicitly
reported; it is not missing evidence or a finite-expiry proof. The source rows
are legacy TOKEN-1.10 and TOKEN-3.8. Skew is a supplied bound, not a measured
clock fact. This implements the native one-skew width predicate; it does not
infer stronger two-clock agreement, instant-specific validity or calibration.

`TOKEN-4.1` selects `delegation`: native inventory and lease-tree replay resolve
every selected lease to the declared birth through an acyclic retained parent
path. Scopes, validity windows, invocation bounds and inherited caveats never
widen; soulbound delegation retains the named delegate. The source rows are
legacy TOKEN-2.4, TOKEN-3.4 through 3.5, TOKEN-3.10 and TOKEN-4.3 through 4.4.
The root scope set is separately retained in the selected artifact, preserving
the legacy reading that a birth token itself carries no scope. Closure concerns
parent resolution inside this selected holding. It establishes neither global
holding completeness nor the legacy complete TOKEN-4.14 closure result.

## Exact selection and evidence

The externally selected TOKEN occurs exactly once in a finite typed namespace
collection. Its immutable payload has exactly `scope`, `clock_unit`, `artifact`.
The scope is `retained-capability-token-records`; the unit is `microsecond`.
`artifact` admits only `clock`, `clock_skew`, `root_scopes`, `tokens_digest`,
`epochs_digest`. Native fields needed by the selected predicate must be retained.
Missing predicate inputs remain UNKNOWN. Unknown artifact/input fields FAIL.

The canonical `verifier-current-token-checks-evidence-1` has exactly
`schema_version`, `objects`, `inputs`. `objects` contains complete namespace
records. `inputs` is null or a map admitting only `tokens` and `epochs`.
The native inventory's birth, aging and lifetime record fields and finite
integer bounds are unchanged. Token and epoch digests commit the exact arrays;
epoch order matters. A nonempty token inventory and exactly one declared birth
are necessary. Windows and delegation additionally require retained leases.
Tenure additionally requires a nonempty retained epoch sequence. Other token
kinds, scopes and unit mappings are unsupported and remain UNKNOWN.

All instants, window widths and skew are integers in microseconds on one named
declared clock. Epoch indices, active-epoch tenure, scope counts and invocation
quotas are dimensionless; no epoch-to-microsecond conversion is inferred.
Signature and key-identifier fields are documentary declarations. The checker
never opens a genesis commitment, loads keys, verifies signatures or executes
token-controlled code. A counterfeit signed declaration may satisfy this narrow
arithmetic proposition; signature validity remains separately unestablished.

Each request binds the exact check, coordinate, proposition digest, TOKEN
identifier and record digest, collection digest, evidence byte reference,
policy digest and finite limits. The policy binds the installed direct and
native implementation sources and these source specifications, labeled roots
and certificate byte ceiling. Labels authenticate no observer and approve no
mapping. No stage number creates a certificate prerequisite: inventory and
composition prerequisites are freshly replayed inline for every predicate.
The partial projections in [CURRENT_TOKEN_FACET_MAPPING.md](CURRENT_TOKEN_FACET_MAPPING.md)
require exact scoped authored rules. Application-mapping authority, complete
facet applicability and host profile selection remain separately required.

Default ceilings are 256 namespace objects, 100,000 native operations,
100,000 composition operations, 4,096 items per container, four mebibytes each
for retained evidence, payload and references, and eight mebibytes per
certificate. One mebibyte is 1,048,576 bytes. Requests may select smaller
positive plain-integer limits; booleans are refused. There are no network
calls, execution hooks or required runtime dependencies.

The `verifier-current-token-checks-certificate-1` embeds exact retained evidence,
request, installed mechanism and proposition digests, native evaluation and
explicit claim limits. Offline recheck requires an independently selected
request and policy, reruns the installed checker and compares complete bytes.
Certificates cannot select their own denominator or host policy.

PASS means only the selected finite predicate reproduced. A rehashed bad fold,
post-revocation revival, false aging count, duplicated replay identifier, empty
window, missing parent, parent cycle, widened scope/window/quota, dropped caveat
or changed soulbound delegate FAILS its relevant predicate. Absent bytes,
required input, unsupported mapping or exhausted valid bounds remain UNKNOWN.
A window no wider than the supplied skew is UNKNOWN, not invalid or valid.
Malformed or substituted requests, policies and certificates are refused
before a computational verdict. Source changes invalidate exact policy pins.

Signature validity, genesis authenticity, living identity, actual execution,
presentation, consumed invocations, fresh revocation observation, real-world
authority, physical clock truth and enforcement remain NOT_ESTABLISHED. Financial
balance/supply semantics, complete domain facets and applicability, whole-tier
qualification, full object conformance and independently admitted mapping
authority remain unestablished. These certificates confer no action authority.

## Contradiction and incompleteness precedence

A finite refutation from exactly retained, supported capability-token fields
outranks an unrelated missing issuer declaration, absent clock label or
unsupported record. Clock provenance is required for cross-token issuance and
window comparisons: absent clock metadata makes those comparisons UNKNOWN,
while dimensionless fold, aging, graph, scope, quota, caveat and delegate
refutations can still FAIL. Unit metadata supplies no missing clock name. Two fully shaped declared births refute the exact-one-birth
inventory prerequisite for each of tenure, windows and delegation; no retained birth remains UNKNOWN. Missing metadata alone still
prevents PASS. The checker first verifies the complete token-array commitment,
then reuses the native inventory parser on its exact supported-record projection
to expose local duplicate identifiers or malformed windows, and reuses the native
tenure fold to expose a retained revival. This projection supplies no replacement
evidence and can never return PASS while an unsupported record is present.

An unsupported record may be an unresolved named parent, so projected absence
does not establish delegation refutation or closure. No authenticity, physical
clock meaning or complete inventory is inferred from partial replay. Valid
resource exhaustion remains UNKNOWN for work that has not established a
refutation within its selected finite bounds. Historical token evaluators retain
their existing semantics; these are explicitly selected current predicates.

Parent membership and cycles are checked before missing root scopes are
reported. Known child-to-parent scope, quota, caveat and delegate contradictions
remain refutable when a root scope set is absent; that absence never supplies
PASS. Retained instants are never normalized, fabricated or compared across an
unproven clock. The missing-clock tenure path replays only the native fold and
aging arithmetic; it never infers issuance ordering. Full original evidence
remains committed and exported in the certificate.

A supported child-to-parent scope contradiction or a cycle wholly among
supported retained leases FAILS even if another unsupported record exists.
Unsupported named parents remain unresolved UNKNOWN, not projected absence.
All supported paths are inspected within the charged budget, so an unrelated
unresolved path cannot mask a later known refutation. Any unsupported record
still prevents PASS and complete delegation closure.

For every selected check, intrinsic lifetime-record scalar syntax requires
plain integer interval bounds and any finite not_after strictly greater than
that same record not_before. This ordered-pair schema condition is refutable
without a clock name; it does not compare instants across tokens, establish
elapsed time, or establish named-clock correspondence. Exactly one fully shaped
declared birth is likewise a shared inventory-validity prerequisite for tenure,
windows and delegation. Cross-token issuance and validity-window relations
require the named clock and remain UNKNOWN when it is absent.
