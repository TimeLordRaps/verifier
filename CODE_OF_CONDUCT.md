# Verifier Standard (VSTD) community conduct

## Expected conduct

VSTD depends on precise disagreement. Participants are expected to:

- criticize claims, specifications, evidence, and implementations rather than people;
- provide a reproducible coordinate or example when practical;
- preserve `UNKNOWN`, `CONFLICTED`, limitations, and counterevidence;
- disclose affiliations or interests that materially affect a proposal; and
- avoid publishing secrets, private data, or vulnerability details in public channels.

Harassment, threats, discriminatory abuse, doxxing, deliberate evidence fabrication,
and sustained disruption are not acceptable.

## Scope and enforcement

This policy applies to project-controlled repositories, issue trackers, review threads,
and project events. The editor may hide or remove abusive content, restrict participation,
or ban an account. Enforcement actions should identify the violated rule without
publishing unnecessary private information.

For ordinary conduct concerns, contact the repository maintainer through a private
GitHub channel. For security vulnerabilities, use the private reporting route in
`SECURITY.md`. This project does not promise confidentiality beyond the controls of the
channel used.

Because governance is currently founder-maintained, enforcement is not independent.
That centralization boundary is disclosed in `GOVERNANCE.md`.
